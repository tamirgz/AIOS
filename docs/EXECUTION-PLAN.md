# AIOS — Recommended Execution Plan

*Written 2026-07-20; status updated 2026-07-23. The single consolidated sequence. Details live in WORKBENCH-PLAN.md (Workbench design/research) and ONE-STOP-PLAN.md (integrations, token policy, distillation strategy); this file is the order of battle.*

## Done (foundation, all shipped & verified)

M0–M10: shell + 10 modules · two-provider AI layer (Claude Max, no key + Ollama, per-job routing) · agents (cron, ledgers, approvals, live transcripts, usage panel) · semantic search over all data + Obsidian vault (local embeddings, configurable model) · Google Calendar (ICS live, API OAuth ready) · Slack in+out (awaiting tokens) · external-report intakes · Ideas pipeline with AI reality-check · ops (daemons, backups, `aios` one-liner) · **two-tier memory: core blocks + archival remember/recall with provenance, consolidation agent enabled**.

**Phase 7 — "Ask" + Notion (2026-07-24).** The NotebookLM replacement. New **`ask` module**: a query box → semantic retrieval over the user's whole corpus (notes, knowledge, Obsidian vault, ideas, tasks, + Notion) → a synthesized answer that **cites its sources inline as [n]**, with clickable source cards. **Ollama-first** — a new `ask` route defaults to free `qwen3-coder:30b` (editable in Settings to escalate to Claude); answers are grounded strictly in the user's data, "I don't have that" when the corpus is silent. New **`notion` module**: a read-only, **token-gated** source — paste a Notion integration token, and pages (title + text) are mirrored into `notion_pages`, embedded by the existing sweep, and folded into `searchEverything` so Ask + search cover Notion too. Degrades gracefully with no token (a connect prompt; everything else works). Net-new = two modules + one table, reusing the whole embeddings/search spine.

**Phase 6 — Gmail read-only (2026-07-24).** New **`gmail` module** on the *same* Google OAuth — the consent scope now includes `gmail.readonly` (one re-consent grants it; calendar keeps working). A `gmail_sync` job (10 min) mirrors the last 7 days of message **metadata only** (from/subject/snippet/received/unread — never bodies) into `gmail_messages`; a Mail page (unread dots, deep links to Gmail, resync) + dashboard widget. Degrades gracefully: until re-consent, the sync returns `needsReconsent` (no crash) and the UI shows a "reconnect Google" prompt. **Feeds the loop:** a `gmail.recent` tool is wired into the **Daily-planner** and **Follow-up tracker** so mail joins the day's plan and post-meeting follow-ups. Triage stays local (the periodic agents already run free/local). Activation = one Connect-Google re-consent in Settings.

**L3 — Chief-of-staff breadth (2026-07-23).** The Life OS gains people-awareness. The Google sync now captures **attendees**; a new **`people` module** derives a light CRM from them (no manual entry) — one row per email with meeting count + first/last seen, a `people_sync` job (30 min) rebuilding it, a People page (per-person meeting history + editable notes) and dashboard widget. Follow-ups get a home: `attention_items` gained a **`personRef`**, so person-anchored cards flow into L1's "Needs you" queue. Three new **free** chief-of-staff agents: **Follow-up tracker** (`qwen3-coder:30b`, weekday evenings — proposes post-meeting follow-ups per person), **Loose-ends chaser** (`qwen3-coder:30b`, Mon/Thu — catches slipping projects/tasks/people), and **Weekly reviewer** (`gemma4:31b-it-qat`, Fri — one synthesis card + remembered priorities). Reuses the whole L1/L2 spine (attention atom, queue, tools); net-new = one table + two columns + one module.

**Free cloud provider + cloud→local fallback (2026-07-23).** Added a third agent provider — **free-tier NVIDIA cloud** (`nvidia`, OpenAI-compatible), **fail-closed to $0 models only** (a run refuses any model not confirmed free in opencode's pricing catalog; verified: a paid `deepseek-v4-flash` run was rejected, a free model ran). Agents gained a **`fallback_model`**: when a cloud primary fails on connectivity/timeout/rate-limit, the executor retries once on the agent's local Ollama model (fresh timeout, logged in the transcript) so the heartbeat survives an offline/flaky cloud. **Then benchmarked the free cloud models on both periodic agents (planner + pulse):** local `qwen3-coder:30b` beat every free NVIDIA model decisively — 4 of 6 cloud models timed out or failed on the multi-turn tool loop (free-tier latency/cold-starts), one did no work, and the one that worked (`llama-3.3-70b`) was 4–6× slower and less accurate. **Conclusion: keep the periodic agents on local `qwen3-coder:30b`;** the cloud path exists with a safe fallback but isn't the right default for a snappy heartbeat.

**L2 — Living projects (2026-07-23).** Projects stop being static folders. Each gains a `goal`, a derived `health` (on_track / at_risk / stalled / blocked) with a one-line reason, and a `lastActivityAt` computed on read across everything linked by `projectRef` (tasks, notes, attention). New **project cockpit**: the grid shows a health chip + next-action + last-active per card; the detail page has a cockpit header (goal & next-action inline-editable, health + reason, rollup stats, and the project's own "Needs you" cards). Health is **never blank** — a deterministic read-time heuristic fills it with zero agent runs, and the **Project-pulse agent** (free local model, 07:00 weekdays) refines it, fills a missing goal/next-action, and raises a card *only* for stalled/blocked projects (idempotent per ISO week). The agent's writes never touch `updatedAt`, so assessing a project can't reset its own stall clock. **Model chosen empirically (2026-07-23):** the exact pulse task was benched across all 12 tool-capable Ollama models, then the top 4 re-run 3× each for consistency. **`qwen3-coder:30b` won decisively** (score 94/100, range 87–97, ~42s) — the only model that repeatedly set correct health on *every* project **and** reliably raised the stall/blocker cards; `qwen3:8b` scored 42 (slow, erratic — one run skipped health entirely). Pulse now runs on `qwen3-coder:30b`; the daily-planner stays on `qwen3:8b` (different workload, not re-benched).

**L1 — Attention spine (2026-07-23).** First slice of the Life OS. New `today` module: the `attention_items` atom + `nextAction` on projects; the **Today** command surface = Plan-my-day (calendar + due tasks + project next-actions, with schedule-to-calendar) + the **"Needs you" queue** that *aggregates* attention items + approvals + Workbench needs_input (not a fourth inbox). The **Daily-planner** agent runs on a **free** local model (qwen3:8b) — `AgentTemplate` now carries `defaultProvider/defaultModel` so the heartbeat can never bill. Verified end-to-end live. W3 delegation-UX is absorbed (its needs_input→Inbox *is* this spine).

**W2 — Executor breadth (2026-07-22 → 23, exit test passed; free cloud verified live 2026-07-23).** Generic CLI adapter: any coding agent is a config row (command template, parser, timeout), not code. opencode/pi/aider seeded; `code-local` task type; per-task executor+model override; Settings panel. Honesty hardened: an executor that prints nothing, or changes no files, is reported as failed, not done. CLI executors run in a local **clone** (real `.git`, correct project root), and `PWD` is pinned to the isolated dir — without which opencode edited the AIOS checkout itself. **Free-model selection** across local Ollama + free cloud (opencode-zen Big Pickle, free Nvidia models), cost-verified from opencode's pricing DB so paid models are refused before spawn; catalog built by file read (pages ~0.01s). **Verified live, all $0:** Big Pickle finished a real edit in 24s, a free Nvidia model (minimax-m2.7) in 133s — both through the Workbench, diffs spec-checked. Root-caused and fixed opencode's startup hang (missing `@ai-sdk/openai-compatible` → `bun install` on every run). **W2 remaining:** pi runs but its JSON parser needs rebuilding against a real fixture; aider is not installed; pi/aider cloud tiers deferred. Detail in WORKBENCH-PLAN §7–§8.

**W1 — Workbench spine (2026-07-21).** 11th module. One-box delegation → executor runs unattended → review in-app. Task/attempt/event schema; supervision engine (git worktree per attempt, per-type timeouts, SIGTERM→SIGKILL on the process group, restart reconciliation, capacity cap 2); claude-headless + native adapters; board + detail with live tail and per-file diff; `workbench.delegate/list/get` tools. Zero worker-code edits — two registry lines, as promised.

## The Life OS (L1–L3) — what it is

The centrepiece from here. AIOS becomes the place you *run* your day/week/projects/ideas via one **attention loop**: living projects (world model) → chief-of-staff agents that **observe** your real activity → a single typed **attention-item** atom → three views (**"Needs you" queue**, **project cockpit**, **Plan-my-day**), governed by a **trust gradient**. It maintains itself instead of asking to be fed. Full design in **ONE-STOP-PLAN §3**; the old "W3 delegation UX" folds into L1's spine.

## Standing principles

- **The heartbeat runs free.** Every periodic/scheduled agent uses a **free model** — benchmarked 2026-07-23, **`qwen3-coder:30b` (local) is the default for the planner + pulse** (correct health + card discipline, ~20-50s; beat both `qwen3:8b` and every free NVIDIA cloud model). `gemma4:31b-it-qat` for the weekly synthesis. A **free-tier NVIDIA cloud** provider exists (fail-closed to $0 models) with a **cloud→local fallback**, but local is the default — the free cloud tier was too slow/unreliable for a heartbeat. Claude is only for one-off, on-demand judgment; the metered-key guard forbids anything paid.
- **Observe, don't ask to be fed.** Derive health, next-actions, follow-ups and loose ends from calendar/email/git/notes and the *absence* of activity — ask only for decisions.
- **Memory is load-bearing**: blocks stay terse (budgets enforced); everything durable goes to archival via `memory.remember`; agents recall before re-deciding; the Sunday consolidation agent keeps both fresh. Nothing important lives only in a chat transcript.
- **Volume, summarization & the heartbeat → local Ollama; one-off judgment & action → Claude Max.**
- **Merge is manual, always.** Agent work stays on its branch until you click.
- **Every phase independently useful; every exit test runs in the real system.**
- Operational: `aios` to start (prod default); migrate ⇒ restart web+worker; never rebuild under a running server; backups nightly at 03:30.
